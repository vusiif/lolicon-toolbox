# 剪贴板来源分析：手动验收

入口：「文本与编码 → 乱码修复 → 剪贴板」。只在点击「读取剪贴板」时读取一次快照；不自动监听，不上传内容。

## 纯文本恢复（PowerShell 7）

下面的 `Set-Clipboard` 会替换系统剪贴板内容，请先保存需要保留的内容。

```powershell
Set-Clipboard -Value '浣犲ソ'
```

1. 先在「粘贴文本」输入 `保留当前输入`，再进入剪贴板页面，点击「读取剪贴板」。
2. 纯文本应显示 `浣犲ソ`，格式列表应有文本格式。来源软件没有提供 HTML 时，右侧按钮不可用。
3. 返回粘贴文本页面，确认原输入仍是 `保留当前输入`。
4. 回到剪贴板页面，点击「使用所选文本」。应回到粘贴文本页面并载入 `浣犲ソ`，旧结果失效，但不会自动分析。
5. 点击本地分析，五候选中应能得到「你好」，转换路径可查看。

## 浏览器与 Word 的多格式文本

可在浏览器或 Word 复制含中文、emoji、换行的文本，然后读取剪贴板。来源软件决定提供哪些格式，可能包括纯文本、HTML、RTF 和 Windows 平台格式。

如需 NBSP 样本，可用 PowerShell 生成一个 HTML 文件，在浏览器打开后复制正文：

```powershell
$clipboardHtmlPath = Join-Path ([IO.Path]::GetTempPath()) ('Toolbox-Clipboard-' + [guid]::NewGuid().ToString('N') + '.html')
$clipboardHtml = '<!doctype html><meta charset="utf-8"><p>ä½&nbsp;å¥½</p><p>第二行 😀</p>'
[IO.File]::WriteAllText($clipboardHtmlPath, $clipboardHtml, [Text.UTF8Encoding]::new($false))
$clipboardHtmlPath
```

1. 复制浏览器中显示的文字后，读取快照。若来源同时提供纯文本与 HTML，应看到两份预览。
2. 比较两份文本，并分别尝试「使用所选文本 → 本地分析」。第一行应能够恢复为「你好」；NBSP 不能被提前换成普通空格。
3. 纯文本与 HTML 可能在末尾换行、段落间距上不同；差异提示不代表其中一份必然乱码。
4. RTF 格式只显示存在和暂不解析，不将其误标为已经恢复。HTML 中图片和非文本对象不加载，若有占位符会提示。
5. 快照读取后再复制别的内容，页面预览应保持不变，直到再次点击「读取剪贴板」。

纯文本与 HTML 内容不同、仅 HTML 存在等情况已用合成 MIME 样本自动验证；真实应用的格式提供情况仍需以上步骤检查。

## 边界、隐私与界面

1. 复制包含 `�` 的文本，检查可能信息丢失的提示。替换字符不能说明丢失的原字节是什么。
2. 在资源管理器复制文件或复制一张图片，若没有可用文本格式，应提示没有可用文本并禁用「使用所选文本」，不能把文件路径当作待修复文件直接打开。
3. 超限样本：`Set-Clipboard -Value ('a' * (1024 * 1024 + 1))`。应提示超过 1 MiB，不能导入该来源；HTML 源码也按 1 MiB 限制。
4. 较大但未超限的样本：`Set-Clipboard -Value ('a' * (100 * 1024))`。预览应最多约 32,768 个 UTF-16 单元，导入仍包含全部 102,400 个字符。
5. 点击「清除快照」，来源预览和导入按钮应清空；系统剪贴板与粘贴文本页的输入保持不变。
6. 小窗口下通过滚动查看全部内容，切换明暗主题后来源选择应清晰。读取期间尝试切换页面或关闭窗口，检查退出情况。
7. 即使已保存 AI API 设置，读取、选择来源与导入也不触发 AI。只有在本地分析后点击「AI 深度分析」才调用已配置的服务。

剪贴板文本已经是 Unicode，不等同于文件原始字节。HTML 提取仅得到文字，编辑器会统一段落和换行分隔；不要将它当作文件原样导出功能。
